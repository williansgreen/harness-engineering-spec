# 任务路由

Harness 应让 agent 在动手前识别任务类型。

## 规划类

触发：

- 设计一个系统。
- 规划软件。
- 这个项目怎么架构。
- 做一个 UI 方案。

默认动作：

- 先规划，不直接大量写代码。
- 明确用户、目标、流程、模块、数据、验证方式。
- 输出可实施的下一步。

## 实现类

触发：

- 实现。
- 添加。
- 修改。
- 接入。
- 完成这个功能。

默认动作：

- 阅读相关代码和 harness。
- 明确验收标准。
- 做最小可验证改动。
- 构建、测试、记录证据。

## Bug 修复类

触发：

- 修复。
- 报错。
- 崩溃。
- 不生效。

默认动作：

- 尽量复现。
- 定位根因。
- 最小修复。
- 增加或更新回归验证。

## Review 类

触发：

- review。
- 代码审查。
- 看看风险。

默认动作：

- 先列缺陷和风险。
- 按严重程度排序。
- 标明文件位置、影响和修复建议。
- 最后再给摘要。

## UI 类

触发：

- 界面。
- 布局。
- 高 DPI。
- 视觉检查。

默认动作：

- 先确认信息架构和状态表达。
- 修改后构建。
- 环境允许时运行并观察。
- 不能运行时说明视觉验收待确认。
