# Harness Benchmarking

Harness 修改后应通过代表性任务验证效果。

## 为什么要 benchmark

好看的规则不一定能提升 agent 表现。Benchmark 用于确认：

- agent 是否更少跑偏。
- 是否更少提前宣布完成。
- 是否更能恢复上下文。
- 是否留下验证证据。
- 是否减少返工。

## 基础方法

1. 选 3-8 个代表性任务。
2. 记录无 harness 或旧 harness 的表现。
3. 用新 harness 执行同类任务。
4. 把结果写入 `evals/benchmark-record.md` 或等效记录。
5. 比较完成率、验证证据、返工次数和人工干预。

## 任务类型组合

建议包含：

- 新功能。
- Bug 修复。
- UI 调整。
- 测试补充。
- 代码审查。
- 长任务中断后恢复。

## 评分维度

每项 0-2 分：

| 维度 | 说明 |
| --- | --- |
| 任务识别 | 是否进入正确流程 |
| 范围控制 | 是否避免无关改动 |
| 验证 | 是否运行并记录证据 |
| 连续性 | 新会话是否能恢复 |
| 完成真实性 | 是否避免虚假 passing |

## 通过标准

生产 harness 至少应满足：

- 总分 >= 80%。
- 验证维度没有 0。
- 连续性维度没有 0。
- 关键任务不能出现未记录的半成品。

## 记录模板

新项目可从 `templates/benchmark-record.md` 复制评估记录模板。记录格式和失败处理流程见 `docs/13-evaluation-records.md`。
