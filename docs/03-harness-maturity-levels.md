# Harness 成熟度分级

## L1 临时 Harness

适用：

- 一次性 demo。
- 教学样例。
- 小型脚本。

要求：

- 有入口规则。
- 有最小构建或运行命令。
- 核心行为至少手动验证。

## L2 项目 Harness

适用：

- 内部工具。
- 原型项目。
- 可能继续维护的应用。

要求：

- 有 `AGENTS.md`。
- 有 feature 状态文件。
- 有构建、测试和质量命令。
- 有会话进度记录。
- 重要决策被记录。

## L3 生产 Harness

适用：

- 多人协作项目。
- 长期维护项目。
- 有真实用户或客户交付。
- 涉及真实设备、数据留存或业务风险。

要求：

- 五子系统完整。
- 每个 feature 有验证证据。
- 有替代验证策略。
- 有审查和回归流程。
- 有 clean-state 收尾要求。

## L4 高风险 Harness

适用：

- 医疗、审计、合规、生产安全。
- 数据错误会造成明显法律、安全或质量风险。

要求：

- 在 L3 基础上加入审计日志、风险记录、权限和发布阻塞项。
- 未验证项目不得被标记为完成。
- 关键路径需要固定样例、边界样例和回归证据。
