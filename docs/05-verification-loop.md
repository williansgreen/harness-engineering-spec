# 验证闭环

本文定义一次改动如何获得完成证据。完整的 agent 执行循环、继续/完成/停止条件见 `docs/15-loop-engineering.md`。

Agent 完成任务时，默认执行以下闭环：

```text
理解需求
  -> 明确验收标准
  -> 检查当前状态和证据基线
  -> 实现最小可验证改动
  -> 构建
  -> 运行相关测试
  -> 检查正常、边界、异常路径
  -> 根据失败形成新假设并调整
  -> 记录证据
  -> 更新状态文件
  -> 决定继续、完成或升级
```

每轮验证必须产生新证据或排除一个可检验假设。原样重复失败命令不算验证闭环。

## 验证优先级

1. 单元测试：纯函数、状态机、解析器、参数校验。
2. 组件测试：服务、持久化、设备适配层、算法管线。
3. 模拟集成：mock server、模拟设备、协议回放、固定样例。
4. 端到端：启动应用并执行关键流程。
5. 人工验证：真实设备、真实环境、视觉检查。

## 替代验证

缺少真实设备、外部服务、授权或数据样本时，不能直接跳过验证。应选择：

- mock。
- 模拟器。
- 协议回放。
- 固定输入输出样例。
- 静态检查。
- 日志检查。

并明确说明仍需真实环境确认的项目。

替代证据不能升级成真实证据：协议 replay 不能证明电机真的停止，命令 ACK 不能证明阀门到位，离屏布局检查也不能证明目标 IPC 的触控和缩放已通过。

## 退出条件

- 通过：当前改动对应的新鲜证据满足验收标准。
- 继续：存在安全、已授权且能产生新信息的下一动作。
- 升级：需要用户选择、额外权限、真实硬件或人工验收。
- 停止：同一失败重复出现且没有新假设，或继续尝试的风险/成本不再合理。

停止时必须记录：

- 失败的命令或验证步骤。
- 当前失败现象。
- 已排除的原因。
- 剩余假设。
- 下一步建议。

不要为所有任务设置统一重试轮数。次数应由动作的成本、可逆性、风险和新信息量决定。

## 完成说明

完成任务时必须说明：

- 改了哪些文件。
- 运行了哪些命令。
- 哪些验证通过。
- 哪些未验证。
- 使用了哪些替代验证。
- 剩余风险是什么。

验证失败时，不得声称任务完成。
